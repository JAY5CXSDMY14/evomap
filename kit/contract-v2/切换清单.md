# 切换清单（U10 部署完成后，同一天执行）

前提：老板已批准 V2.0 五条修订，并同意安装 Orca。

1. 备份：把现行 `协作契约/01-契约-AGENT-CONTRACT.md`、`03-验收队列协议.md` 复制到 `协作契约/备份/V1.0-<日期>/`。
2. 装套件：`bash kit/install.sh` 检查 → 补缺 → `bash kit/install.sh --apply`；Orca 里打开 Orchestration；手机扫码配对。
3. 先空跑：用假工人（`kit/mock/`）在副本仓库跑一遍，`evo status` 三个闸门都出现。
4. 替换契约：把本目录两份文件覆盖到 `协作契约/`，在 `待批准变更清单.md` 签署 V2.0。
5. 更新各岗位启动 prompt 里引用的条款号（§0、§3.4、§3.5、§7、§11.7、§12）。
6. 冻结 wb-issues 面板为只读历史。
7.5 magpie 统一管理（装套件后、真跑前）：
   - Library 里从 GitHub 装 DietrichGebert/ponytail 的 ponytail 和 ponytail-review 两个 skill，只发给施工、验收用的 agent（DSH、Claude Code、Codex），记下装的提交；有更新只看不自动升，看过再点更新。
   - 建两个路由组 group/evo-build、group/evo-verify，成员不重叠；全局配置 roles.build.models / roles.verify.models 写组名。
   - 先试 `dsh` 能否单次指定模型（`{model}` 参数）；不能就给 evo 单开一个 DSH profile，默认模型设成 group/evo-build，老板手动用的 DSH 不受影响。
   - evo 岗位提示里仍点名「按 ponytail full 执行」「按 ponytail-review 清单验收」，kit 内留固定版文本兜底。
7. 真跑第一件：挑一件非 UI 小任务，看施工→验收→合并全自动走完；再挑一件 UI 小件验证「看效果」。

回退：`launchctl unload ~/Library/LaunchAgents/com.evoloop.autopilot.plist`，把备份的 V1.0 两份文件拷回，按老办法手贴继续。

## 补充（多项目版）

- 面板：`evo panel`，确认左上角能切到「土布」，「全部待办」里能看到看效果闸门。
