## A 一句话
```callout ok 软装已备齐，在 Hark 沙箱用假工人整套跑通
到 Mac mini 上装一次，你只剩三处点头：做不做、看效果、上线。
```

## B 由哪些项目拼成
| 部件 | 取自 | 管什么 |
|---|---|---|
| 发动机 | Orca | 独立工作区、派工、回报、心跳、闸门、手机端 |
| 模型入口 | magpie | 岗位只写模型名，额度用完自动换号 |
| 接棒器 | 本仓库 evo（旧名 tubu） | 施工、验收、合并的接力，冲突排队，返工，停滞提醒 |
| 统一入口 | 本仓库 | GitHub issue 打标签就登记，先过脱敏词表 |
| 夜间复盘 | yetone 的做法 | 同一教训出现 3 次升为规矩 |
| 审查岗 | 代码审查仓库 | 云端只读代码，问题回流入口 |
| 规矩 | Mac mini 协作契约 | 红线和证据全保留，另有 5 条修订待批 |

## C 一件事怎么走
```flow LR
[issue] -> [做不做 仅产品] -> [施工] -> [验收 换模型] -> [看效果 仅UI] -> [合并] -> [上线 攒一批]
```

## D 沙箱实测
| 场景 | 结果 |
|---|---|
| 不同目录的两件 | ok 同时开工 |
| 同目录的后一件 | ok 等前一件合并后才开工 |
| 施工和验收的模型 | ok 自动错开 |
| 三个闸门 | ok 都能卡住，点了才放行 |
| 验收不通过 | ok 自动返工，复验过了自动合并 |
| 工人没动静 | ok 标疑似卡住并提醒 |
| 你点「不做」 | ok 这件直接撤掉 |

## E 你要做的四步
1. 批 5 条契约修订，同意装 Orca。
2. Mac mini 上跑安装脚本：先检查，再加 `--apply` 正式装（只装本机环境和常驻，不碰项目，可反复跑）。
3. 用 `evo import` / `evo new` 登记项目。
4. 手机装 Orca App 扫码配对。

## E2 配置分两层
| 层 | 位置 | 管什么 |
|---|---|---|
| 全局 | `~/.evoloop/config.json` | 岗位和模型、整机并行上限、提醒、夜间时间、magpie 地址 |
| 项目 | `~/.evoloop/projects/<代号>/config.json` | 仓库、主分支、GitHub、测试/推送/上线命令、脱敏词表、错题本 |

项目可用 `overrides` 覆盖全局；整机并行上限只认全局。老配置照旧能用。

## E3 自动化测试
`kit/tests/` 用假 Orca、假工人、假通知（不联网）、临时仓库和裸远端跑整条流水线。各种岔路都有测试，时间用 `EVO_NOW` 固定。GitHub Actions 每次改 kit 自动跑。现在共 120 个测试。

## E4 提醒：只在该叫你的时候叫你
| 通道 | 干什么 |
|---|---|
| outbox | 每件事一行记进 `~/.evoloop/outbox.jsonl`，永远开着，外部 Agent 读这里 |
| Telegram | 只推要你知道的事；闸门消息带「通过 / 打回」按钮，打回后回一句话就是原话；只认你本人 |
| 邮件 | Telegram 不通时兜底，另收早晚汇总 |
| webhook | 把事件 POST 给 Muse 或别的 bot，可带签名 |
| macOS | 本机通知照旧 |

只推六类：闸门 5 分钟没人管、件卡住（含接棒器心跳停了）、推送连续失败 3 次、额度用完暂停、用量异常、上线失败。0:00–8:00 不打扰，8:30 一条早间汇总。`evo notify-test` 一键试所有通道。

## E5 外部 Agent：能看、能报，不能批、不能上线
```callout warn 硬规矩
外部 Agent 只能读状态和事件、开 issue（agent-report）或 evo feedback；写进来的都当不可信。批闸门、上线只能你本人；删数据、改线上、花钱、对外发布这四类请求一律转给你。
```
详见 `docs/agent-interface.md`（`evo status --json` 有 `schema_version`，字段只加不改）。

## E6 额度、用量、时间窗、决策岗
| 项 | 怎么做 |
|---|---|
| 订阅额度用完 | 岗位暂停到重置时间（看不出就 60 分钟），这件原样重排，不算失败不算返工，到点自动恢复 |
| 用量 | 每个项目/岗位记派工次数和工人分钟，配了 magpie 用量再记 token；一件超上限推一次；没有花钱上限 |
| 面板 | 第一次开随机生成口令，存钥匙串；所有接口都要口令 |
| 时间窗 | `--window trading:cn` 只在 A 股交易时段开工，窗外显示「等窗口」 |
| 决策岗 | 交决策岗、有提问、外部来报攒一批，至多 30 分钟叫醒一次 |

## E7 施工交卷、范围、git 守卫
| 检查 | 不合格时 |
|---|---|
| 施工按 JSON 交卷（状态、改动、真跑过的测试、未完成、风险、看效果要点） | 没按格式、没做完、测试红 → 返工；卡住 → 交决策岗 |
| 改动只落在本件 scope（证据目录 artifacts/ 例外） | 交付时、合并前各查一次，越界就返工，不送验收 |
| 主仓库 .git/config 没被 Agent 改坏 | 自动复原；复原后仍指错 → 项目暂停 |

## E8 第十轮：岔路补齐、少找你、停了能知道
| 项 | 现在怎么走 |
|---|---|
| 决策岗的决定 | 按 JSON 交（重试、带说明返工、拆分、不做、转老板、回答提问），evo 自动执行；交不好件留到下一批 |
| 施工提问 | 决策岗的答复带进新一轮施工（Orca 暂无回复命令，先用返工兜底，不扣轮次） |
| 缺标签的 issue | 只交决策岗一次，补好后自动登记 |
| 上线 | 先跑上线命令，成功才标已上线并关 issue；失败推送给你，件留在可收菜 |
| 崩溃 | 每个动作后立即存盘，重复的 Orca 消息跳过 |
| 合并冲突 / 合并前测试红 | 自动返工让施工 rebase 修好，超上限才交决策岗 |
| 收菜 | 每天 08:20 后自动建上线闸门（主线绿才建），Telegram 一点就上线 |
| 它自己停了 | 每轮写心跳；10 分钟没转动推一次；面板/接口有 `last_tick` |
| 夜审错过 | 当天过点照跑，第二天中午前补昨天 |
| Mac 睡眠 | install.sh 检查并给出防睡眠命令 |

## F 只能在 Mac mini 上验
| 项 | 为什么 |
|---|---|
| 真工人按说明回报 | 沙箱没有你的账号 |
| 同一工具各用各的模型 | 要看 magpie 实际行为 |
| Hook 日志和手机提醒 | 依赖你的机器 |
| Orca 读终端的字段、真工人额度提示原文 | 沙箱里是假 Orca、假工人 |
| Telegram 按钮、钥匙串授权框 | 要真账号、真 Mac |
| Orca 消息号字段、重投行为；真决策岗交 JSON | 去重和决定回流依赖它们 |
| 真上线命令退出码、launchd 定时看门狗、pmset 输出 | 沙箱没有 |
