这页按你会碰到的十个场景写：你看到什么、你要定什么、evo 自己做什么、边角情况。最后是真正要你拍板的几件事，每件都带我建议的默认。

## A 一句话 {span=3}
```callout ok 第十四轮已实现（kit 有自动测试，应用 v0.4.0 有「团队」页）
每个岗位是一张卡：工具 + 模型 + 思考档位 + 一句话职责 + 备用。模型只从 magpie 来，evo 不存任何密钥。额度满了自动切备用，到点切回；模型下线、施工验收撞模型、magpie 不通都会停下并告诉你怎么改。哪个模型更好看 evo 自己的数据，只给建议，换不换你点。外部 Agent 永远改不了模型。
```

| 借 todos.dev 的想法 | 在 evo 里变成什么 |
|---|---|
| Agent = 名字 + 岗位 + 运行工具 + 模型 + 思考档位 | 岗位卡片：施工 / 验收 / 决策，每张卡写 tool、models、thinking、duty、fallback |
| 供应商配一次，密钥不落到机器上 | 只配 magpie 一处；evo 配置里没有任何 key，CLI 用它自己的登录 |
| 模型下拉框 = 供应商目录 | 下拉框 = magpie `/v1/models` 列表 + 卡片现有 + 成绩表里出现过的 |
| 外部 CLI 列它自己的模型 | `tools.<工具>.models` 可写这个 CLI 自己的目录；没写就不判它 |
| 下线的模型标出来 | magpie 标了 retired，或上次还在这次不见了 → 卡片红灯「模型已下线」 |
| 每个账号的用量 | 卡片上「本周 N 次 · M 分钟（账号）」，按订阅账号合计 |
| 额度用完换运行工具、保留上下文 | 额度满切到卡片的备用；同一个工作区接着做，下一次派工生效，正在跑的不打断 |
| 不做插件 | 不做。magpie 是唯一的模型来源（127.0.0.1:3425） |

## B 一张岗位卡长什么样 {span=3}
| 字段 | 例子 | 说明 |
|---|---|---|
| tool | codex | 运行工具：claude / codex / dsh / pi。决定账号（额度一起满） |
| via | cli 或 magpie | 模型走工具自带，还是走 magpie。模型名是 `group/…` 时自动当 magpie |
| models | gpt-5-codex | 可以写 magpie 组名 `group/evo-build` |
| thinking | high | off / low / medium / high / max；命令里有 `{thinking}` 才会填进去 |
| duty | 按任务书写代码和测试，交 JSON 报告 | 一句话，卡片上给你看 |
| fallback | dsh · group/evo-build | 主模型额度满、magpie 不通、模型下线时用；最好是另一个账号 |

全局写在 `~/.evoloop/config.json` 的 `roles.<岗位>`，项目要特殊就写项目配置 `overrides.roles.<岗位>`。改法都走一个命令：`evo team set <岗位> --model … [--project 代号]`，应用里的下拉框和输入框也走它。

## C 1 第一次装 {span=3}
| | 内容 |
|---|---|
| 你看到 | 向导第 3 步「定岗位」：一张小清单。比如「施工：dsh · group/evo-build，备用 codex」「验收：claude · 工具默认模型，备用 dsh · group/evo-verify」「决策：claude · 思考 high」，下面是缺什么的提醒 |
| 你定 | 点「就这样」。不满意点「跳过」，以后在「团队」页换 |
| evo 自动做 | `evo team init` 看本机装了哪些 CLI（claude / codex / dsh / pi），猜登录了没有；问 magpie 有哪些模型和组；按三条原则配：施工和验收不同家、决策用最强的、每张卡尽量配一个不同账号的备用。`--apply` 只写 roles 里这几个字段，别的配置不动 |
| 边角 | magpie 没开：走 magpie 的卡先不建，提示开好再跑一次。一个 CLI 都没有：不写，告诉你装哪个。已经有配置：照样只改这几张卡。外部 Agent 跑向导：拒绝 |

## D 2 每天瞄一眼 {span=3}
| | 内容 |
|---|---|
| 你看到 | 主窗口侧栏「团队」。每张卡：状态灯 + 一句状态、工具胶囊、模型下拉框、思考档位、一句职责、备用、每个模型的成绩、一句建议、本周用量。顶上一颗「magpie 通 / 不通」。下面「各项目」一行一个项目，三个岗位各标「跟随全局」或「本项目专用 · 模型」 |
| 状态灯 | 绿「可用」；黄「用备用中」「额度满 · 17:00 恢复」（会自己好）；红「没装」「未登录」「模型已下线」「模型不认识」「和施工撞模型」「magpie 不通」（要你动手）；灰「没配置」 |
| 你定 | 平时什么都不用定。红灯才需要你看一眼 |
| evo 自动做 | 健康检查每 5 分钟一次（magpie 列表 + CLI 在不在、登录文件在不在），缓存在 `~/.evoloop/team_health.json`；用量和成绩从各项目时间线现算 |
| 边角 | 「未登录」只是猜（看 `~/.claude/.credentials.json`、`~/.codex/auth.json` 这类文件），真机以能不能跑为准；只显示，不拦派工 |

## E 3 半夜额度满了 {span=3}
```flow LR
[施工 codex 额度满] -> [记暂停到重置时间] -> [这件原样重排 不扣轮次] -> [下次派工用备用 dsh] -> [到点切回 codex]
```
| | 内容 |
|---|---|
| 你看到 | 夜里没有推送。早上 8:30 的早间汇总里多一行「切到备用：施工岗额度满，已切到备用 dsh · group/evo-build」。团队页施工卡黄灯「用备用中」 |
| 你定 | 什么都不用定 |
| evo 自动做 | 认出额度提示（回报正文或终端尾部）。这个账号的岗位记暂停到重置时间。有备用的岗位不推「额度暂停」，改记「切到备用」（时间线 + outbox）；这件原样重排，同一个工作区接着做。正在跑的别的件不打断，它们交卷或也碰到额度时才轮到。到点自动解除暂停，记「切回主模型」，下一次派工用回主模型 |
| 边角 | 备用和主模型是同一个账号：等于没备用，照旧暂停并推送。备用也满了：两边都停，推一次「额度暂停」。没配备用：和以前一样暂停 + 推送。白天发生：只记 outbox，不推（见 L 第 2 条） |

## F 4 magpie 不通 {span=3}
```callout warn 我的决定：走 magpie 的岗位停下，工具自带模型的照跑
magpie 管的是模型和 key。它不通时，走 magpie 的卡没有别的路能拿到同一个模型；悄悄退到工具自带的默认模型，等于换了一个你没选过的模型，还可能让施工和验收变成同一家。所以：有「工具自带」备用的卡切备用；没有的停下等；用工具自带模型的卡（比如 claude、codex 直连）不受影响。
```
| | 内容 |
|---|---|
| 你看到 | 推一次「magpie 不通」（夜里进早间汇总）。团队页顶上红点，受影响的卡红灯「magpie 不通」，件的状态写「等 magpie」 |
| 你定 | 重启 magpie。要是常出这种事，给走 magpie 的卡配一个工具自带的备用 |
| evo 自动做 | 健康检查发现由通变不通才推（只推一次）；恢复后记「magpie 恢复」，下一次派工自动接上，不用你点 |
| 边角 | 正在跑的工人不打断。magpie 不通时不判断「模型在不在列表里」，免得误报下线 |

## G 5 magpie 里出现新模型 {span=3}
| | 内容 |
|---|---|
| 你看到 | 团队页顶上一条「新模型可用：qwen3-coder-plus」，带「试用…」和「收起」。outbox 里一条事件，不推送 |
| 你定 | 要不要试；试的话挑一个项目、一个岗位（「在 TB 试施工」） |
| evo 自动做 | 每次健康检查对比 magpie 列表：第一次只记下不提醒；之后新出现的合成一条建议。试用 = 在那个项目写「本项目专用」加试用标记（默认 5 件）；满了发一条对比（试用模型 vs 原模型的打回率、返工、漏放），不自动留用 |
| 边角 | 收起后不再出现。试用中途想停：`evo team clear <岗位> --project 代号`；想留：点「换成」或 `evo team set … --project 代号`，试用标记自动去掉 |

## H 6 哪个模型更好 {span=3}
| 指标（近 30 天，来自时间线） | 施工模型 | 验收模型 |
|---|---|---|
| 验收打回率 | 它做的件被验收打回的比例 | — |
| 每件返工轮数 | 返工次数 ÷ 件数 | — |
| 看效果打回率 | 你点打回的比例 | — |
| 分钟/件 | 派工到交卷 | 每次验收的分钟 |
| 没活路次数 | 它做的件被判「没有活路」 | — |
| 漏放率 | — | 它放行后又被你看效果打回的比例 |

| | 内容 |
|---|---|
| 你看到 | 卡片里每个用过的模型一行成绩，当前模型高亮；下面一句建议，例如「建议验收换成 group/evo-verify：它放过去又被你打回的只有 0%，现在的是 20%（各验了 9 / 21 次）。点『换成』才生效」，旁边一个「换成 …」按钮 |
| 你定 | 点不点「换成」 |
| evo 自动做 | 只建议，绝不自己换主模型。少于 5 件不下结论；差距不到 15 个百分点说「不用换」。决策岗不比成绩，只提醒「用最强的」 |
| 边角 | 不同项目难度不同，成绩是全部项目合计；项目页看得到本项目的试用对比 |

## I 7 某个项目要特殊 {span=3}
| | 内容 |
|---|---|
| 你看到 | 「各项目」里 ST 一行：「施工 本项目专用 · claude-opus-4.1」，其他是「跟随全局」 |
| 你定 | 哪个项目、哪个岗位、用什么。例：选股评分引擎要更强模型。跑 `evo team set build --model claude-opus-4.1 --project ST`，或在输入框写「ST 的施工换成 claude-opus-4.1」 |
| evo 自动做 | 写项目配置 `overrides.roles.build`；全局怎么换都不影响它；`evo team clear build --project ST` 回到跟随全局 |
| 边角 | 项目专用的卡同样过安全栏（撞模型、模型下线都会拒绝） |

## J 8 换一个模型 {span=3}
```flow LR
[卡片下拉框 或 输入框 把验收换成 X] -> [确认卡] -> [确认换] -> [evo team set] -> [下一次派工生效]
```
| | 内容 |
|---|---|
| 你看到 | 输入框上面弹出一张确认卡：「把验收从 claude-sonnet-4.5 换成 group/evo-verify？全局，所有跟随全局的项目一起换。下一次派工生效，正在跑的不打断。」两个按钮「算了 / 确认换」 |
| 你定 | 确认或算了 |
| evo 自动做 | 先在副本上改、过安全栏，过了才落盘；回一句「验收（全局）：claude · group/evo-verify。下一次派工生效」 |
| 边角 | 输入框认得：「把验收换成 X」「施工模型改成 X」「本项目把施工换成 X」「ST 的施工换成 X」。认不出的照常当反馈发。外部 Agent（设了 EVO_AGENT）用命令行、面板接口改，一律拒绝，看可以 |

## K 9 安全栏 {span=3}
| 规则 | 什么时候拦 | 你看到的修法 |
|---|---|---|
| 施工 ≠ 验收 | 改配置时：新模型和另一岗位有重叠（含 magpie 组成员）就不改。派工时：这件施工用的模型和验收撞了，验收先挑不撞的；全撞就停 | 「施工和验收不能用同一个模型（含 magpie 组成员）：ds」；件写「等换模型」，推一次「验收岗停了」 |
| 模型下线 / 不认识 | magpie 通、模型走 magpie、却不在列表里（或标了下线、或上次在这次没了） | 「模型 X 已从 magpie 下线」，推一次，带 `evo team set build --model <模型>` |
| 决策用贵模型 | 决策卡的模型看起来不是最强档（名字或 `model_tiers` 判断） | 卡片黄字提醒，不拦 |
| 外部 Agent | 设了 EVO_AGENT 的任何改动 | 拒绝，说明只能老板本人改 |
| 模型名 | 不是字母数字和 `. _ : / @ + -` | 拒绝（模型名会进工人命令行） |

## L 10 用量和花费 {span=3}
```callout info 和已定的规矩一致：不设钱的上限
记用量（次数、分钟，按账号合计一周），额度满先切备用，没备用再暂停岗位。单件超过次数或分钟上限照旧推「用量异常」。
```
| | 内容 |
|---|---|
| 你看到 | 每张卡「本周 19 次 · 426 分钟（codex）」；`evo team` 底部按账号合计；magpie 有用量接口时，status 里另有 token |
| 你定 | 不用定。觉得某账号用太多，就给它的卡换模型或换备用 |
| evo 自动做 | 每次派工在时间线记账号和工具；回报时算分钟 |

## M 需要老板拍板 {span=3}
| # | 问题 | 我建议的默认（现在就是这么做的） |
|---|---|---|
| 1 | magpie 不通、卡片又没配工具自带的备用时，是停下，还是退到工具自带的默认模型接着跑？ | 停下并推一次。理由见 F：不悄悄换你没选过的模型 |
| 2 | 额度满切到备用，白天要不要推送？ | 不推，只记 outbox；夜里发生的进早间汇总。备用也满了才推 |
| 3 | 「建议换模型」的门槛？ | 每个模型至少 5 件（验收 5 次），差 15 个百分点以上才建议；永远只建议 |
| 4 | 决策岗用什么？ | claude 最强档，思考 high，配不配备用随你；不拿成绩比 |
| 5 | 新模型试用默认几件、在哪试？ | 5 件，只在你点的那个项目、那个岗位；满了给对比，留不留你点 |

## N 只能在 Mac mini 上验 {span=3}
| 项 | 为什么 |
|---|---|
| 各 CLI 的命令模板 | `codex --model … -c model_reasoning_effort=…`、`pi --thinking …`、`dsh --model …` 按文档猜的；claude 没有思考档位参数（只填模型） |
| 「未登录」的判断 | 看登录文件在不在；macOS 钥匙串里的登录看不到，可能误报 |
| magpie 组成员字段、下线标记 | `/v1/models` 是否带 members、retired / deprecated；没有就只比名字 |
| 备用在同一个工作区续做 | 不同工具读同一个工作区没问题，但对话上下文不会带过去，靠任务书里「接着做，不要从头来」 |

## O 命令和接口 {span=3}
| 命令 / 接口 | 作用 |
|---|---|
| `evo [-p AB] team [--json] [--refresh]` | 岗位卡片、健康、成绩、建议、各项目徽章（`--json` schema_version 1） |
| `evo team set <岗位> --model M [--thinking L] [--tool T] [--duty …] [--fallback-model M] [--fallback-tool T] [--no-fallback] [--project AB]` | 改卡片（拒绝外部 Agent，过安全栏） |
| `evo team clear <岗位> --project AB` | 回到跟随全局 |
| `evo team trial <岗位> <模型> --project AB [--items 5]` | 试用 |
| `evo team init [--json] [--apply]` | 首次安装向导 |
| `evo team dismiss <模型>` | 收起新模型建议 |
| `GET /api/team[?code=AB]`、`POST /api/team` | 面板接口，要口令 |
| `evo status --json` 新增 `team`、`roles[].fallback`、件的 `waiting` 多了 `model_blocked` / `magpie_down` | 只加字段，schema_version 仍是 1 |
