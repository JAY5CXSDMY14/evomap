## A 结论
```callout ok 借 6 处小而实的，不搬它的大架子
Paperclip（paperclipai/paperclip，MIT）是 Node 服务加 React 面板加 Postgres，管一整个「AI 公司」：组织架构、招聘审批、预算、目标对齐。evo 只管「一件事从施工到上线」，组织架构和招聘用不上。值得借：面板上几处让人放心的设计，加一个防「全停了没人管」巡检。
```

## B 建议借的 6 处
| 序号 | Paperclip 的做法 | 放进 evo 的样子 | 价值 |
|---|---|---|---|
| 1 | 任务巡检员：一棵任务全停下且没有「活路」时，叫一个 agent 读证据，判断停得对不对，不对就重新推起来 | 「无活路」检查：每件没完结的事必须有一条活路（有工人在干、有闸门等某人、在排队）；没有就交决策岗，并在面板标红 | 高：补上「大家都在等别人」的死锁 |
| 2 | 产出物预览：agent 产出的 HTML、图片直接在面板里看，iframe 沙盒隔离 | 看效果闸门里直接显示 artifacts/ 下的截图和 HTML 报告，不用去开应用 | 高：你点「通过」更快 |
| 3 | 首页看板：岗位忙闲、各状态件数、卡太久的件、用量和消耗速度 | 面板首页加「岗位状态」一行（忙、闲、暂停、额度满）和「卡太久」清单 | 中 |
| 4 | 活动记录：每次变化记谁、做了什么、旧值到新值，可按件筛 | 每件一条时间线：派工、交卷、打回原话、合并、上线，点开看 diff 和记录 | 中：出事好查 |
| 5 | 确认卡会过期：你在讨论里补了新话，旧的「接受吗」自动作废；确认卡绑定版本号 | 看效果闸门已绑改动指纹；再加一条：你对某件写了新反馈，它等你的旧闸门自动作废重开 | 中 |
| 6 | 目标对齐：任务连到项目目标，agent 拿到「为什么做」 | 项目配置加一行项目目标，自动写进每份任务书开头 | 低成本 |

细节见 kit/README.md「第十二轮」；status --json 只加字段，版本号不变。

| 1 | 已实现 | 每轮查每件的活路；30 分钟没有就交决策岗一次，面板标红，status --json 有 no_live_path | 真决策岗会不会对这类件给出 retry / drop |
| 2 | 已实现 | 看效果闸门卡片和件页显示 artifacts/：图片、沙盒 iframe 里的 HTML（只许脚本、断网）、下载链接；带口令、防目录穿越、5MB 上限 | 真浏览器里沙盒和断网的效果 |
| 3 | 已实现 | 项目页顶上岗位状态一行（忙、闲、暂停、额度满），「没有活路」「卡太久」两个清单 | 换皮后的样子 |
| 4 | 已实现 | 每个项目一份只追加的时间线；件页看时间线、交卷、diff；evo log 命令 | 无 |
| 5 | 已实现 | 补新反馈（命令、件页、issue 评论）就作废等你的旧闸门，改完重开；作废的闸门点了不执行 | 真 Orca 手机端怎么显示「作废」 |

## C 不借的
| 东西 | 原因 |
|---|---|
| 组织架构、招聘审批、CEO 战略审批 | evo 的岗位是固定的几个，换人在配置里改 |
| 按 agent 的预算上限 | 已定不设花费上限，只盯异常和额度暂停 |
| Postgres + Node 服务 | evo 状态在本机文件，够用且好备份 |
| 每次运行必须留言 | evo 已要求 JSON 交卷，作用相同 |

## D 顺带
- 它审外部 PR 时放进 Docker，不碰本机登录。以后若接受别人的 PR，审查岗可照这个做。
- 它的产出预览禁止 allow-same-origin，面板做预览时照这条写。
