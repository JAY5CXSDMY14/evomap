## A 一句话
```callout ok 软装已备齐，在 Hark 沙箱用假工人整套跑通
到 Mac mini 上装一次，你只剩三处点头：做不做、看效果、上线。
```

## B 由哪些项目拼成
| 部件 | 取自 | 管什么 |
|---|---|---|
| 发动机 | Orca | 独立工作区、派工、回报、心跳、闸门、手机端 |
| 模型入口 | magpie | 岗位只写模型名，额度用完自动换号 |
| 接棒器 | 本仓库 evo（旧名 tubu） | 施工、验收、合并的接力，冲突排队，返工，停滞提醒 |
| 统一入口 | 本仓库 | GitHub issue 打标签就登记，先过脱敏词表 |
| 夜间复盘 | yetone 的做法 | 同一教训出现 3 次升为规矩 |
| 审查岗 | 代码审查仓库 | 云端只读代码，问题回流入口 |
| 规矩 | Mac mini 协作契约 | 红线和证据全保留，另有 5 条修订待批 |

## C 一件事怎么走
```flow LR
[issue] -> [做不做 仅产品] -> [施工] -> [验收 换模型] -> [看效果 仅UI] -> [合并] -> [上线 攒一批]
```

## D 沙箱实测
| 场景 | 结果 |
|---|---|
| 不同目录的两件 | ok 同时开工 |
| 同目录的后一件 | ok 等前一件合并后才开工 |
| 施工和验收的模型 | ok 自动错开 |
| 三个闸门 | ok 都能卡住，点了才放行 |
| 验收不通过 | ok 自动返工，复验过了自动合并 |
| 工人没动静 | ok 标疑似卡住并提醒 |
| 你点「不做」 | ok 这件直接撤掉 |

## E 你要做的四步
1. 批 5 条契约修订，同意装 Orca。
2. Mac mini 上跑安装脚本：先检查，再加 `--apply` 正式装（只装本机环境和常驻，不碰项目，可反复跑）。
3. 用 `evo import` / `evo new` 登记项目。
4. 手机装 Orca App 扫码配对。

## E2 配置分两层
| 层 | 位置 | 管什么 |
|---|---|---|
| 全局 | `~/.evoloop/config.json` | 岗位和模型、整机并行上限、提醒、夜间时间、magpie 地址 |
| 项目 | `~/.evoloop/projects/<代号>/config.json` | 仓库、主分支、GitHub、测试/推送/上线命令、脱敏词表、错题本 |

项目可用 `overrides` 覆盖全局；整机并行上限只认全局。老配置照旧能用。

## E3 自动化测试
`kit/tests/` 用假 Orca、假工人、假通知（不联网）、临时仓库和裸远端跑整条流水线。各种岔路都有测试，时间用 `EVO_NOW` 固定。GitHub Actions 每次改 kit 自动跑。现在共 170 个测试。

## E4 提醒：只在该叫你的时候叫你
| 通道 | 干什么 |
|---|---|
| outbox | 每件事一行记进 `~/.evoloop/outbox.jsonl`，永远开着，外部 Agent 读这里 |
| Telegram | 只推要你知道的事；闸门消息带「通过 / 打回」按钮，打回后回一句话就是原话；只认你本人 |
| 邮件 | Telegram 不通时兜底，另收早晚汇总 |
| webhook | 把事件 POST 给 Muse 或别的 bot，可带签名 |
| macOS | 本机通知照旧 |

只推六类：闸门 5 分钟没人管、件卡住（含接棒器心跳停了）、推送连续失败 3 次、额度用完暂停、用量异常、上线失败。0:00–8:00 不打扰，8:30 一条早间汇总。`evo notify-test` 一键试所有通道。

## E5 外部 Agent：能看、能报，不能批、不能上线
```callout warn 硬规矩
外部 Agent 只能读状态和事件、开 issue（agent-report）或 evo feedback；写进来的都当不可信。批闸门、上线只能你本人；删数据、改线上、花钱、对外发布这四类请求一律转给你。
```
详见 `docs/agent-interface.md`（`evo status --json` 有 `schema_version`，字段只加不改）。

## E6 额度、用量、时间窗、决策岗
| 项 | 怎么做 |
|---|---|
| 订阅额度用完 | 岗位暂停到重置时间（看不出就 60 分钟），这件原样重排，不算失败不算返工，到点自动恢复 |
| 用量 | 每个项目/岗位记派工次数和工人分钟，配了 magpie 用量再记 token；一件超上限推一次；没有花钱上限 |
| 面板 | 第一次开随机生成口令，存钥匙串；所有接口都要口令 |
| 时间窗 | `--window trading:cn` 只在 A 股交易时段开工，窗外显示「等窗口」 |
| 决策岗 | 交决策岗、有提问、外部来报攒一批，至多 30 分钟叫醒一次 |

## E7 施工交卷、范围、git 守卫
| 检查 | 不合格时 |
|---|---|
| 施工按 JSON 交卷（状态、改动、真跑过的测试、未完成、风险、看效果要点） | 没按格式、没做完、测试红 → 返工；卡住 → 交决策岗 |
| 改动只落在本件 scope（证据目录 artifacts/ 例外） | 交付时、合并前各查一次，越界就返工，不送验收 |
| 主仓库 .git/config 没被 Agent 改坏 | 自动复原；复原后仍指错 → 项目暂停 |

## E8 第十轮：岔路补齐、少找你、停了能知道
| 项 | 现在怎么走 |
|---|---|
| 决策岗的决定 | 按 JSON 交（重试、带说明返工、拆分、不做、转老板、回答提问），evo 自动执行；交不好件留到下一批 |
| 施工提问 | 决策岗的答复带进新一轮施工（Orca 暂无回复命令，先用返工兜底，不扣轮次） |
| 缺标签的 issue | 只交决策岗一次，补好后自动登记 |
| 上线 | 先跑上线命令，成功才标已上线并关 issue；失败推送给你，件留在可收菜 |
| 崩溃 | 每个动作后立即存盘，重复的 Orca 消息跳过 |
| 合并冲突 / 合并前测试红 | 自动返工让施工 rebase 修好，超上限才交决策岗 |
| 收菜 | 每天 08:20 后自动建上线闸门（主线绿才建），Telegram 一点就上线 |
| 它自己停了 | 每轮写心跳；10 分钟没转动推一次；面板/接口有 `last_tick` |
| 夜审错过 | 当天过点照跑，第二天中午前补昨天 |
| Mac 睡眠 | install.sh 检查并给出防睡眠命令 |

## E9 第十一轮：看过的不白看、死了自己起、写法和模型
| 项 | 现在怎么走 |
|---|---|
| 看效果指纹 | 你点「通过」时记下这件改动的指纹。之后若因冲突或测试红返工，合并前再算一次。没变直接合并；变了重开看效果闸门并照常推送，写明「解冲突/返工时改了你看过的内容」。`relook_on_change: false` 关掉 |
| 工人进程死了 | 在原工作区、同岗位、同模型自动重启一次并记日志；同一次派工重启后再死，才标疑似卡住推给你。已经交了回报再退出的不算死 |
| Ponytail 写法 | 施工按 full 档最小完整改法（任务书验收标准优先），收尾的「跳过 / 没查 / 风险」写进交卷；验收按 review 清单，必须修打回、应该修只建议另开 issue，每条要有触发情形。提示词固定副本在 `kit/vendor/ponytail/`（MIT，固定提交） |
| 每周体检 | 每周日（`audit_weekday`，0=周一 … 6=周日）夜审时给决策岗放一条「跑 ponytail-audit」待办，只提醒不自动跑 |
| 默认模型 | 全局 `roles.build.models` / `roles.verify.models` 可写 magpie 组名；`evo models`（install.sh 也跑）核对 magpie `/v1/models` 里有没有、施工验收是否重叠，只警告 |
| 装进 Evo 应用 | 常驻进程不写字节码缓存；在应用包里跑时本机通知默认交给应用发，配置写明了就听配置 |
| 单项目换模型 | 面板项目页「施工模型 / 验收模型」下拉框，选项来自 magpie，读不到就手填，另有「跟随全局」；写进项目 `overrides`。要口令，外部 Agent 改不了，模型名只许安全字符 |

## E10 第十二轮：借 Paperclip 面板 6 处
| 项 | 现在怎么走 |
|---|---|
| 无活路检查 | 每轮查每件没完结的事。有工人在干、有闸门在等、在排队、返工已排上，都算有活路。超过 30 分钟（`limits.no_live_path_minutes`）没有活路就交决策岗一次，面板标红，`status --json` 有 `no_live_path`。决策岗照旧用 retry / rework / drop / ask_owner 处理 |
| 看效果时直接看产出物 | 看效果闸门卡片里列出本件的 `artifacts/`。图片直接显示，HTML 放进沙盒 iframe（只许脚本、不给同源权限、CSP 断网），其余给下载链接；单个文件上限 5MB。施工交卷里的「请看」清单一起显示 |
| 首页 | 项目页顶上一行岗位状态（忙 / 闲 / 暂停 / 额度满），另有「没有活路」「卡太久」两个清单（同一状态超过 6 小时，`limits.stale_hours`） |
| 每件时间线 | 派工、交卷、开闸门、通过/打回（带原话）、返工、合并、推送、上线、工人重启、决策岗决定都记一行。点件进件页看，可开 diff；命令行 `evo -p TB log TB-FIX-012` |
| 新反馈作废旧闸门 | 你对某件补了新话（`evo feedback --item`、件页「补充反馈」、或在它的 issue 下评论），它等你的看效果 / 做不做闸门立刻作废；看效果的带着原话返工，验收过了再开新闸门；旧闸门上点什么都不执行 |
| 项目目标 | 项目配置一行 `goal`；`evo new/import --goal`、`evo goal set`、面板项目页都能改（要口令，外部 Agent 不行）；每份任务书第一行「项目目标：…」 |

## E11 第十三轮：UI 栈预设
老板的原则：优先复用成熟库、组件源代码可控、统一设计语言、严格限制重复依赖。

| 项 | 现在怎么走 |
|---|---|
| 开关 | 项目配置 `ui_preset`：`web-react` / `swiftui` / `none`（默认，不加任何东西）。`evo new/import --ui-preset`、`evo -p AB ui set …`；外部 Agent 只能看不能改 |
| Web 默认栈 | shadcn/ui（Nova，组件源码进仓库）+ Tailwind、Lucide、Motion、react-resizable-panels、dnd-kit、Zustand；建议补齐 react-hook-form + zod、TanStack Query、TanStack Table、sonner、Recharts、date-fns。每类有「不另加」清单 |
| 原生 Mac / iOS | 系统组件优先、SF Symbols、原生弹簧动画、Swift Charts、Observation；第三方 UI 库要你批准 |
| 换库 | 你批准后 `evo -p AB ui set icons=react-icons` 写进 `ui_overrides`；`icons=` 清掉 |
| 旧项目 | 只管新代码，不迁移。仓库某一类已在用别的库，现有的赢，日志和提醒只报一次；`evo -p AB ui show web-react` 可以先预览 |
| 任务书 | 碰界面的件：施工任务书在项目目标后带「UI 规范」，验收任务书带「UI 规范检查」 |
| 自动把关 | 交卷后送验收前比依赖清单：新加禁用库 / 同类第二个库直接打回；lockfile 里才有的、手写已有组件、没写理由的新依赖只提示（时间线可见）。验收岗可跑 `evo -p AB ui check` |
| 现有项目 | ST 用 `swiftui`；TB 不动，土布 web 先预览现有栈冲突再决定 |

## E12 第十四轮：模型协调
```callout ok 岗位卡片 + 额度满切备用 + 模型成绩，有自动测试（本轮 26 个）
每个岗位一张卡：工具、模型、思考档位、一句职责、备用。模型只从 magpie 来，evo 不存密钥。详细的场景和要你拍板的事见 `docs/model-coordination.md`。
```
| 场景 | evo 怎么做 |
|---|---|
| 额度满 | 有另一账号的备用就切过去，不推送（夜里的进早间汇总）；到点切回 |
| 模型下线或写错 | 这个岗位停下，推一次，告诉你怎么换 |
| 施工和验收撞模型 | 改配置时拒绝；派工时挑不撞的，挑不到就停 |
| magpie 不通 | 走 magpie 的岗位切工具自带的备用或停下；工具自带模型的照跑 |
| 哪个模型更好 | 团队页给每个模型的成绩和一句建议；只建议，换不换你点 |
| 新模型 | 团队页提示，可在一个项目、一个岗位先试 5 件 |
| 外部 Agent | 改不了模型 |

## E13 第十七轮：修体检的高危 + 你批的三条规矩
```callout ok 先保证不卡死、不误合并，再保证不误伤、不白跑
体检报告的高危 7 条全修了（L-07 要真机验），中危顺手修了几条。体检附录的 4 段复现脚本都改成了测试。
```
| 问题 | 现在 |
|---|---|
| 常驻进程一直占锁，你点什么都卡住 | 每一轮起一个子进程，做完就放锁；改的配置下一轮就生效 |
| 一轮在跑时看不到状态 | 看状态只读，不等锁；暂停时也能看，写明暂停原因 |
| 一条坏消息让项目每轮崩 | 每条消息单独兜错，坏的只记一次、交决策岗一次；迟到的旧回报直接丢掉 |
| 在 Orca 手机端点了「打回」，evo 照样合并 | 打回、不做照办；通过、上线不直接算数，推「确认上线 TB-FIX-012？」，你在 Telegram、App 或面板再点一次才生效。工人在 Orca 里结闸门也不算数。这是试运行（开关 `orca_gate_sync`），你真机用过再调 |
| 外部命令卡住，整台机器停 | 测试、git、gh、推送、上线、一整轮都有超时；超时按失败处理 |
| 土布拉远端不走代理 | 项目配置 `git_env`，git 和 gh 都带代理（没写就从推送命令里认） |
| 远端主线红了，在途的件全被当成自己的错返工 | 先看主线本身红不红；主线红就让件等着，不算返工；只推一次，只登记一件修主线 |
| 推送失败每 30 秒重试一次 | 1、2、4……最长 30 分钟退避 |
| 决策岗卡住没人管 | 45 分钟没交就关掉重叫；连续两次推给你 |
| gh 登录过期，入口安静地停了 | 拉不到 issue 不影响这一轮；连续 3 轮推「gh 登录失效」 |
| evo 在你的桌面工作副本里合并 | evo 在 `~/.evoloop/repos/<代号>` 自己克隆一份，合并、推送都在那里；你的副本 evo 不碰，你要看就 `git pull`。已登记的项目跑一次 `evo -p TB relocate` |
| 一件可以无限返工、无限烧时间 | 决策岗指导返工 2 次后转你；一件派工 12 次或工人累计 6 小时就暂停，推「已烧 6 小时还没完，继续还是不做？」。三个数字在面板「每件上限」或 `evo limits` 改 |

## F 只能在 Mac mini 上验
| 项 | 为什么 |
|---|---|
| 真工人按说明回报 | 沙箱没有你的账号 |
| 同一工具各用各的模型 | 要看 magpie 实际行为 |
| Hook 日志和手机提醒 | 依赖你的机器 |
| Orca 读终端的字段、真工人额度提示原文 | 沙箱里是假 Orca、假工人 |
| Telegram 按钮、钥匙串授权框 | 要真账号、真 Mac |
| Orca 消息号字段、重投行为；真决策岗交 JSON | 去重和决定回流依赖它们 |
| 真上线命令退出码、launchd 定时看门狗、pmset 输出 | 沙箱没有 |
| Orca 对死掉工人的判定（`worker-show` 的 observation / orphaned） | 自动重启靠它，假 Orca 只模拟了 exited |
| magpie `/v1/models` 是否列出组、组有没有成员字段 | 重叠检查要成员；没有就只比名字 |
| 真浏览器里沙盒 iframe 预览 HTML 产出物、图片显示 | 沙箱只测了接口和页面源码 |
| 真 Orca 闸门「作废」写法 | evo 用 gate-resolve 写结果「作废（有新反馈）」，要看真 Orca 和手机端怎么显示 |
| GitHub 评论时间和 `<!-- evo -->` 标记 | 新反馈只认闸门开之后、可信作者、不带标记的评论 |
| 真模型按「UI 规范」选库、shadcn CLI 在本机代理下能否跑 | 沙箱里是假工人 |
| 各 CLI 的命令模板、「未登录」的猜法、magpie 组成员和下线标记 | 第十四轮模型协调按文档猜的，要真机核对 |
| 真 Orca 的闸门列表会不会列出已结的闸门、结果字段名 | 第十七轮「Orca 端结闸门」靠它（试运行） |
| TB 迁到专用克隆后 fetch 走代理、Orca 认新目录 | 要你的网络和 Orca |
