```callout ok 已实现 v1（10-21）：菜单栏小应用已经能用命令行打出 Evo.dmg，详见 G 节；界面 v1.1 重做见 H 节
还没在真机上点过：通知授权、钥匙串、开机自启、Gatekeeper 都要在 Mac mini 上验一遍。
```

```callout ok 值得做，但做成「菜单栏小应用」，不照 Todos 的大架子，等 Mac mini 跑顺两周再开工
evo 现在确实是一个正经项目了。做成 dmg 的价值在安装和日常使用：一个图标装好、菜单栏随时看到「等你几件」、点开就是面板、出错有原生通知。Todos 是 Electron 桌面壳加云端服务端加手机网页的整套产品，evo 不需要云端，照抄只会多出一大块要维护的东西。
```

## B Todos 是怎么搭的
| 层 | Todos | evo 对应 |
|---|---|---|
| 桌面壳 | Electron 44，约 150 MB，内嵌 Expo 网页前端 | 没有；面板是本机网页 |
| 本机守护进程 | tds（Node），无状态，只认领、执行、上报 | evo 常驻进程（Python，launchd） |
| 状态机与交棒 | 云端服务端，闭源，不在 dmg 里 | evo 本机自己管，状态在 ~/.evoloop |
| 通知 | Web Push、应用内事件流、Electron 原生通知，「正在看就不弹」 | Telegram、邮件、webhook、macOS 通知 |
| 手机 | 网页加扫码登录 | Telegram 按钮 |
| 闸门 | 方案确认、改动验收，都在回合之间 | 做不做、看效果、上线，也在回合之间 |

## C 三条路
| 路 | 是什么 | 体积 | 优点 | 缺点 |
|---|---|---|---|---|
| 1 保持现状 | 命令行 + launchd + 网页面板 + Telegram | 0 | 已经能用，改动最快 | 安装靠脚本；看状态要开浏览器 |
| 2 菜单栏小应用（推荐） | SwiftUI 菜单栏图标 + 内嵌现有网页面板 + 打包好的 evo | 约 30 MB | 一键安装；角标显示等你几件；原生通知点了直达那件；开机自启；口令进钥匙串 | 要多维护一个壳；Python 要一起打包 |
| 3 照 Todos 做整套 | Electron 壳 + 云端服务 + 手机网页 | 不小于 150 MB | 手机原生体验，可给别人用 | 要养服务器；工作量是 evo 本身的几倍；和「只在本机跑」相反 |

## D 推荐方案长什么样
- **菜单栏图标**：角标是「等你点头」件数；下拉列出各项目状态和上次转动时间；暂停、继续、立即转一轮。
- **主窗口**：直接嵌现有面板网页，不重写界面；面板改一处，应用里同步。
- **首次打开向导**：检查 Orca、magpie、git、gh；导入项目（evo import）；填 Telegram 用钥匙串存；一键装开机自启。代替现在的 install.sh。
- **evo 本体**：用 PyInstaller 或独立 Python 打成一个可执行文件放进应用里，不依赖系统 Python。命令行 evo 仍然可用，指向同一个文件。
- **通知**：沿用 Todos 的规则，面板窗口正在看就不弹；点通知直接打开那一件。
- **签名**：自己用不必付费签名，第一次右键「打开」即可；要发给别人再考虑 99 美元的开发者账号。

## E 为什么不现在做
```callout warn 先让内核在真机上稳定
evo 还有不少只能在 Mac mini 上验的点：Orca 真实回报、模型额度提示、Telegram 按钮。壳做早了，内核一改壳也跟着改。先装 evo 跑两周，把 TB 跑顺，再把壳加上。到时候 evo 自己也导入成一个项目（代号 EV），让循环来开发这个应用。
```

## F 顺带从 Todos 借的
| 机制 | 用处 |
|---|---|
| 完成事件先落盘再发 | evo 已有 outbox；施工回报这一侧可以再加一层 |
| 权限请求一律拒绝而不是挂着 | 施工遇到权限弹窗不等人，直接交决策岗；和现在规则一致，可写得更硬 |
| 每轮结束打 checkpoint，可回退 | 返工前留点，打回时能回到上一版 |
| 回合中插话 | 你在面板对正在干的件补一句，不用等它交卷 |
| 每件单独记方案、diff、记录、花费 | evo 已记用量，可补上 diff 和记录链接 |

### 和 D 节设想不同的地方
- **python 没打包**：先用本机 python3（Homebrew 优先），应用才 1 MB。真要发给别人再考虑 PyInstaller。
- **暂停或恢复**：停的是 launchd 常驻（bootout），不是改项目状态；重新登录后常驻会自动回来。
- **点通知**：打开面板首页，还不能直达那一件；面板要先支持带件号的地址。
- **导入项目、填 Telegram**：向导里还没有，仍用命令行 evo import 和环境变量。

### 要在 Mac mini 上验的
| 项 | 怎么验 |
|---|---|
| 第一次打开 | 拖进应用程序后右键打开；macOS 15 要去隐私与安全性里点仍要打开 |
| 通知授权 | 第一次启动会问；设置里发一条测试通知 |
| 钥匙串 | 口令由 evo 存，应用经系统 security 工具读，一般不弹框；弹了就点始终允许 |
| 开机自启 | 设置里打开后注销再登录；要批准就去系统设置的登录项 |
| 常驻指向 | 向导里安装前先把应用放进应用程序；之后别挪 |
| 重复通知 | evo 自己也会弹 macOS 通知；装了应用后把全局配置里 notify.macos 改成 false |

### 留给后面
- 点通知直达那一件，需要面板支持带件号的地址。
- 向导里加导入项目和 Telegram 口令进钥匙串。
- install.sh 写常驻时加上不写 pycache 的环境变量。现在靠应用包里 bin 目录只读兜底。
- 要发给别人时换开发者证书签名并公证。

### 弹窗里有什么
| 区块 | 内容 | 背后的命令 |
|---|---|---|
| 头部 | 小陶、问候（按钟点）、时间、状态胶囊：运行中、已暂停、心跳过期、出错了；小陶用气泡说一句现状 | 只读 status |
| 等你处理 | 每个闸门一张卡：项目、件号、标题、种类、等了多久；两个按钮取闸门自己的两个选项（通过和打回、做和不做、上线和再等等）；看效果打回先写原话 | evo -p 代号 approve 闸门号 选项 原话 |
| 项目 | 施工、验收、等你、卡住四个数；下面小字是卡太久件数和岗位状态；点一行只看这个项目 | 只读 status |
| 快捷胶囊 | 立即 tick、打开面板、暂停或恢复、收菜 | evo tick、evo panel、launchctl、evo ship |
| 输入框 | 选项目和方式后回车；evo 的回话以小陶气泡显示 | 反馈走 evo feedback，新件走 evo add --scope . |
| 命令面板 | ⌘K 打开；动作、每个闸门的两个选项、每个项目都能模糊搜 | 同上 |

快捷键：⌘1 到 ⌘9 只看第几个项目，⌘回车 通过当前卡片，⌘K 命令面板，⌘R 刷新。

### 跟上第十二轮 status 字段
- no_live_path 和 stale 在顶层是件列表，应用只数个数：卡住取 stuck 和 no_live_path 件数的较大值；stale 显示成卡太久。
- roles 是岗位状态列表，项目行下面显示一行，比如施工忙、验收闲。
- 字段缺了、类型不对都不报错；列表里个别条目坏了只跳过那一条。

### 逻辑放在哪
界面要的数据都在 EvoCore 里算好。包括问候、状态胶囊、闸门卡片、项目行、小陶心情和台词。还有模糊过滤、命令面板、输入框命令、收菜清单、快捷键、小陶每一帧的姿态。单元测试从 21 个加到 32 个，Linux 上也能跑。
