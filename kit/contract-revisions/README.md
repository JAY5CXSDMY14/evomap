# 协作契约修订草案（待老板逐条批准；AI 不得自行改契约，契约 §10）

装好精装房之前，这 5 条必须先批，否则自动接棒与契约冲突。每条都给出原文位置、改成什么、为什么。

**改好的全文**在 `kit/contract-v2/`（01、03 两份，可整份替换）；切换步骤与回退见 `kit/contract-v2/切换清单.md`。

## 修订一 · 岗位不写死工具（01 全文）
- 现：标题「三智能体」，条文点名 Codex / DSH / Claude Code / WorkBuddy。
- 改：条文只写岗位（决策、施工、验收、审计、审查、中台）；谁担任写在 `kit/config.json` 与 evo 团队配置（`evo team set`）。
- 为什么：换模型、换工具不必再修契约。

## 修订二 · 推进信号源（03 §6、§7；01 §3.5 第 4 条）
- 现：老板是唯一推进信号源；没有投递通道就由老板手贴。
- 改：接棒器（tubu + Orca）按岗位自动接棒；老板只在三处点头：做不做（仅产品功能）、看效果（仅 UI）、上线。手贴只作故障兜底。
- 为什么：03 §7 当初约定「跑满 20 件再议自动触发」，现已 127 份任务书。

## 修订三 · 有限并行（01 §3.4 第 1 条；§3.5 第 7 条）
- 现：一轮只做一件；不开第二 DSH。
- 改：范围（目录）不重叠才并行，施工最多 2 路；重叠的自动排队，等前一件合并。等老板的事超过 5 件时暂停新施工。
- 为什么：沙箱预演已验证排队与闸门可靠。

## 修订四 · 事实源（01 §7、§9 末行）
- 现：唯一面板 wb-issues，只有 WorkBuddy 能改。
- 改：问题统一进 GitHub issue；每件进度以 Orca 任务状态为准，`evo status` 与 Orca 手机端是老板看板。
- 为什么：WorkBuddy 已转任，面板职责交中台。

## 修订五 · 合并与推送（01 §11、§11.6）
- 现：验收官验收通过后推送。
- 改：验收通过（UI 件再加看效果）后，由接棒器对齐主线、重跑测试、`merge --no-ff` 合并；不改写历史、不强推（R7 不变）。上线仍等老板。
- 为什么：推送权从「人」移到「闸门」，证据链不变。

## 不改的（新流程必须遵守）
红线 R1–R10；§4 验收即命令；§5 证据落盘；§6 脱敏（登记前扫词表，命中不登记）；§8 例外上报；R9 施工与验收独立且换模型。
