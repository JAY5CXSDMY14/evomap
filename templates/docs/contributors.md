# 外部贡献审查

外部 PR 与 Issue 一样只是"需求和线索"，代码进入 main 之前**先查危害，再看功能**。

## 1. 立即停下、等维护者的情形（任一命中）
- 修改 CI / 工作流 / 发布脚本 / 构建配置
- 新增外部网络地址、遥测、上传
- 读写凭证、token、密钥文件，或改鉴权逻辑
- 新增依赖、二进制文件、压缩包、混淆或生成的大段代码
- 修改安装脚本、自动更新逻辑
- 批量删除数据或用户文件

Reviewer 加 `evo:needs-human`，评论列出命中项和文件位置，不运行 PR 中的代码。

## 2. 直接关闭不审的情形
- 与产品边界明显冲突，或推翻已拍板决定
- 大量无关改动混在一起，且作者拒绝拆分
- 明显由工具批量生成、未经验证的 PR

## 3. 正常审查
通过第 1、2 节后，与内部 PR 相同标准审查（code-standards 全文）。必要时由 Builder Agent 基于外部 PR 的思路重新实现，并在 commit 来源中致谢作者。

## 4. 拉黑
Agent 只能**提议**拉黑，附证据（PR 链接、命中项），由维护者决定。被要求"额外谨慎"的作者列在下方：
