## A 一句话
```callout warn 五条修订批了，自动循环才合法
红线、验收即命令、证据、脱敏全部不动；改的只是谁来传话、能不能并行、谁来合并。
```

## B 一件事的流程：改前 vs 改后
```flow LR
[老板贴任务书] -> [施工] -> [老板贴回报] -> [验收] -> [老板贴结论] -> [验收官推送]
```
```flow LR
[issue 自动登记] -> [做不做 仅产品] -> [施工] -> [验收 换模型] -> [看效果 仅UI] -> [自动合并] -> [上线 攒一批]
```

## C 五条修订总表
| # | 改什么 | 现在 | 改后 | 理由 |
|---|---|---|---|---|
| 一 | 岗位写法 | 点名四个工具，标题叫三智能体 | 只写岗位，谁担任写在配置里 | 换模型换工具不用再改契约 |
| 二 | 谁推进 | 老板是唯一推进源，没通道就手贴 | 接棒器自动传，老板只点三处 | 复制粘贴和人不在就停，是最大痛点 |
| 三 | 并行 | 一次一件，不开第二个 DSH | 目录不重叠才并行，最多两路 | 快一倍，重叠的自动排队不打架 |
| 四 | 看板 | wb-issues，只有 WorkBuddy 能改 | GitHub issue 加 Orca 任务状态 | WorkBuddy 已转任，看板不能绑一个工具 |
| 五 | 合并 | 验收官通过后自己推送 | 闸门过后接棒器测一遍再合并 | 推送权从人移到闸门，证据链不变 |

## D 你点头的地方：改前 vs 改后
| 环节 | 现在 | 改后 |
|---|---|---|
| 派任务 | 每件都要你贴 | 不用管 |
| 施工到验收 | 你传话 | 自动 |
| 技术选型和权限 | 常常问你 | 决策岗定，只有删数据、改线上、花钱才问你 |
| 做不做 | 每件 | 只有产品功能 |
| 看效果 | 不固定 | 只有 UI |
| 上线 | 每件 | 攒一批点一次 |

## E 不改的规矩
| 规矩 | 说明 |
|---|---|
| 红线 R1–R10 | 不碰定稿、不编造、不强推等全部保留 |
| 验收即命令 | 没有命令输出就不算过 |
| 证据落盘 | 每件留证据目录 |
| 脱敏 | 登记前扫词表，命中就不登记 |
| 施工与验收分开 | 而且必须换模型 |
| 改契约 | 仍然只有你能批 |

## F 安全阀
| 情况 | 怎么处理 |
|---|---|
| 等你的事超过 5 件 | 暂停开新工 |
| 返工两轮还不过 | 交决策岗换方案 |
| 合并时测试不绿 | 不合并，提醒 |
| 工人 15 分钟没动静 | 标疑似卡住，提醒 |
| 自动化坏了 | 退回手贴兜底 |
