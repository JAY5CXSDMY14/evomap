# 岗位而非工具：角色可替换规则

老板 2026-10-20：角色不固定在某个 Agent 上，看到更好的就换，包括 Codex、Claude Code、DSH、Pi。

## 原则
1. **契约写岗位，不写产品名。** 条款说「施工位只能提请验收」，不说「DSH 只能提请验收」。担任者写在 `profiles/<项目>/roles.yaml`。
2. **三权不因换人而合并。** 同一个会话不能同时担任 决策 + 施工、施工 + 验收。同一款工具可以担任两个岗位，但必须是**两个独立会话**、各读各的启动 prompt（例如 cc 既做循助又做验收官）。
3. **门禁按岗位生效。** hook 识别当前会话的岗位（不是识别工具），岗位决定 deny 规则。

## 换人检查单（试用新 Agent 前逐项过）
| 项 | 要求 | 不满足时 |
|---|---|---|
| 指令入口 | 能读项目 AGENTS.md / CLAUDE.md 或等价文件 | 包一层启动 prompt |
| hook | 至少 PreToolUse + PostToolUse + Stop，能 deny | 不能担任施工位、验收位 |
| 权限 | 能用 allow/deny 白名单跑命令，不需要 bypass | 不能担任验收位 |
| 证据 | 命令真实输出能落进 `.hook-logs` | 不能担任验收位 |
| 传话 | 支持当前传话层的至少一种方式 | 保持手工 |
| 成本 | 写清每轮 token / 订阅限制 | 只做短任务 |

## 试用流程
1. 副本仓库、一件小任务、原担任者保持待命。
2. 跑完一轮后对比：返工次数、越权次数、卡死次数、老板手动介入次数。
3. 老板点头后改 `roles.yaml` 与启动 prompt；契约条款不动。
