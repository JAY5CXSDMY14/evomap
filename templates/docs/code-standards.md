# Code Standards

> Reviewer 逐条核对本文件。Builder 请求 review 前自查本文件。
> 「来自复盘的硬标准」一节由夜审 Agent 维护：LESSONS.md 中 Seen 3× 的教训会被升级到这里。

## 1. 验收条件（合并或发布前必须展示全部）

| # | 条件 | 怎么证明 |
|---|---|---|
| A1 | **回退必挂（Red check）**：存在一个没有本次改动就会失败的测试 | 把旧代码放回去运行，贴出失败信息；编译失败、测试被跳过**不算**失败 |
| A2 | **隔离环境**：测试不读写真实配置和真实数据 | 说明使用的临时 HOME / 临时库 / mock |
| A3 | **全量检查通过** | 格式、lint、类型、全量测试、构建，逐项写结果 |
| A4 | **UI 改动的多环境验证** | 至少两个浏览器引擎；多语言项目覆盖所有语言；窄屏 |
| A5 | **真实使用**：涉及外部服务、真实配置格式时，用真实账号/真实返回验证 | 写明验证方式；做不到就写 Not run，且**不得对用户宣称可用、不得在其上继续开发** |
| A6 | **没跑的写出来** | 每个没运行的检查列在 Not run，绝不省略 |

## 2. 改动范围

- 一个 commit / PR 只做一个目标；顺手发现的问题另开 Issue。
- 修一类不修一例：grep 同类路径、同形态守卫、所有调用方，一起修或写明理由。
- 改动必须在完整路径上成立：从用户输入追到最终结果（调用方、状态、副作用）。
- 改了子系统的行为 / 状态 / 契约 → 同 PR 更新 `docs/subsystems/<name>.md`。
- 不推翻 `AGENTS.md`「已拍板的产品决定」。

## 3. 测试

- 测试数据使用报告人的原始字节 / 原始配置，不自己编"差不多"的样例。
- 测试永不加载真实第三方页面或真实接口；用保存下来的真实响应在本地起服务。
- 以"保证某事"命名的测试，在保证被破坏时必须失败（Break check 验证）。
- 测试启动的进程、端口、临时文件随测试结束而清理。
- 时序相关的测试两侧留余量；负载下才失败也算真问题，开 Issue。
- flaky 测试找根因（注入延迟复现），不靠重跑碰运气。

## 4. 用户数据

- 程序默认值永不覆盖用户自己设置的值；写之前列出该设置被读取的所有位置。
- 读取 / 解析 / 哈希失败 = **未知**，绝不当成"空"或"相等"。
- 删除或覆盖前，找出所有可能匹配同一 key 的记录。

## 5. 红测试

- main 上的红测试就是现在要修的 bug，不是基线。
- 声称"main 上也一样失败"，必须是刚 `git fetch` 的 `origin/main`，并写明 sha。

## 6. 合并

- Reviewer 将 PR head 合到最新 main 后重跑检查，**只看 diff 不算 review**。
- 先在 PR 上写 Review 评论（审过的 sha + 运行记录），再合并。
- 合并命令：`gh pr merge <n> --squash --match-head-commit <reviewed-sha>`；Review 后 head 变化 → 重审。
- PR 自己新增的测试失败、或 Review 列出的问题未解决 → 不合并。
- Issue 不在合并时关闭；等报告人确认后关闭；报告人说没好 → 重开并标 `evo:regressed`。

## 7. 发布

- 目标 commit 的 CI 已完成且全绿才打 tag；cancelled 的 run 不算通过。
- 攒批发布：两次发布间隔不少于 {{MIN_RELEASE_INTERVAL}}，P0 除外。
- 所有产物上传完成才算发布；告诉用户某版本前确认它真的存在。

## 8. Commit 规范

标题：
```
<area>: <用户现在看到的行为>（<来源>）
```
- `<area>`：子系统名，如 `api`、`web`、`search`、`lessons`、`docs`
- `<来源>`：`#123`、`张三 on 微信群`、`the owner: <原话>`

正文（超过 {{BODY_REQUIRED_LINES}} 行改动必须有正文；建议总是写）：
```
Why: 原因，含定位过程（日志、profile 数据）
What: 改了什么
Red: <测试名> 在没有本改动时失败：<失败信息>
Ran: <命令> → <结果>（逐项）
Not run: <没跑的检查及原因>
Known: 已知 flaky / 未覆盖的部分
```

## 9. Review 评论模板

```markdown
Reviewed `<pr-head-sha>`, merged onto main `<main-sha>`. <Merging | Changes requested | Needs human>.

**Harm check:** 改了哪些文件；是否新增网络请求、凭证读写、依赖、CI 变更、数据删除。

**What was run** (环境说明):
- **Red check.** 旧代码下 `<test>` 失败：「<信息>」；带改动通过。
- **Break check.** 将 `<条件>` 改为 `<破坏方式>`，`<test>` 失败：「<信息>」。
- 全量：<命令> → <结果>
- 构建 / 类型 / lint：<结果>

**Read:** 读代码得出的结论（路径是否一致、兄弟路径是否覆盖）。
**Standards:** 逐条核对本文件，列出不满足项或"全部满足"。
**Not run:** <没跑的及原因>
```
