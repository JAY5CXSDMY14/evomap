## A 一句话
```callout ok 你只管方向和效果，其余自己转
所有问题进同一个 issue 队列。中台按任务书自动接棒、并行推进不冲突的活。你只在三处点头：做不做、看效果、上线。岗位是位子，坐谁随时换。
```

## B 整体拓扑：谁连着谁
```flow LR
[Agent 读仓库发现] -> *GitHub issue 队列
[网页用户反馈] -> 反馈转发器 -> GitHub issue 队列
[你在面板提需求] -> GitHub issue 队列
[CI 与线上报警] -> GitHub issue 队列
[夜间复盘] -> GitHub issue 队列
[云端审查岗] -> GitHub issue 队列: 只建 issue
GitHub issue 队列 -> *中台调度器
中台调度器 -> 决策岗 -> 施工岗 -> 验收岗
验收岗 --> 施工岗: 不过退回
验收岗 -> [合并到主线]
中台调度器 -> *面板
状态守护 -> 面板
状态守护 --> [手机推送]
面板 -> (你)
手机推送 --> 你
[(hook 日志)] -> 状态守护
审计岗 --> GitHub issue 队列: 账本问题
group Mac mini: 中台调度器, 决策岗, 施工岗, 验收岗, 状态守护, hook 日志, 审计岗
group 五类来源: Agent 读仓库发现, 网页用户反馈, 你在面板提需求, CI 与线上报警, 夜间复盘
```

## C 一件事的状态机
```flow TB
(新来源) -> 待分诊
待分诊 -> {产品或体验类?}
{产品或体验类?} -> *等你：做不做: 是
{产品或体验类?} -> 可派工: 纯技术
*等你：做不做 -> 可派工: 做
*等你：做不做 --> [不做，回复原因]: 不做
可派工 -> {和进行中的冲突?}
{和进行中的冲突?} --> 排队: 冲突
排队 --> 可派工: 冲突解除
{和进行中的冲突?} -> 写任务书: 不冲突
写任务书 -> 施工中 -> 验收中
验收中 --> 施工中: 不过，最多 2 轮
验收中 -> {有界面变化?}
{有界面变化?} -> *等你：看效果: 有
{有界面变化?} -> 自动合并: 没有
*等你：看效果 -> 自动合并: 通过
*等你：看效果 --> 施工中: 退回
自动合并 -> 待上线
待上线 -> *等你：上线 -> (关闭)
```

## D 你睡一晚，它怎么推进
```sequence
你 -> 中台: 22:00 批了 A、C 的「做」
中台 -> 施工岗: 开工 A
施工岗 -> 验收岗: A 交卷
验收岗 -> 中台: A 通过，有界面变化
中台 -> 你: A 进「等你看效果」，不打扰睡觉
note 中台: B 和 A 改同一块，排队
中台 -> 施工岗: 开工 C
施工岗 -> 验收岗: C 交卷
验收岗 -> 中台: C 通过，纯技术
中台 -> 中台: C 自动合并
== 早上 ==
你 -> 中台: A 通过
中台 -> 中台: A 合并，B 自动开工
```

## F 为什么审查岗可以放云端
```callout info 审查只要看代码，不碰 Mac mini
审查岗按 -agent-code-review 的 PLAYBOOK 工作：读 GitHub 上的代码，结果只写成 code-review issue，状态记在 issue 末尾。所以 Grok、Codex 云端这类自带电脑的 Agent 都能直接接，换人只改配置。它只需要一把「读代码 + 建 issue」的钥匙，不需要 Mac mini 的任何权限。
```

## G 和 Mac mini 现有机制对照（初步）
| 现有 | 处理 | 原因 |
|---|---|---|
| 任务书 / 交付 / 验收 三个队列目录 | warn 保留，改由中台读写 | 证据文件仍有用，但不再人工搬运 |
| 循助人工传话、派工话术 | no 替换 | 中台命令行直接接棒，你不再复制 |
| 每一棒都要你三行审批 | no 替换 | 改成只在三处点头，技术棒自动走 |
| 授权目录与 hook 守卫 | ok 保留并补强 | 加白名单和权限请求日志，卡住能被发现 |
| WorkBuddy 面板 | warn 逐步退场 | 由 Multica 或自建面板接任 |
| Hark 15 分钟盯梢 | no 替换 | 换成 Mac mini 上 30 秒一次的状态守护 |
| Pi 横向审计 | ok 保留 | 结果改为直接建 issue |
