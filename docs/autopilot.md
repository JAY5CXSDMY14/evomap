# 自动推进（土布）

老板 2026-10-20：方向、任务书定好后，它应该自己实施、推进，到需要通过时再来问。A 做完等批时，继续推进不冲突的 B；B 冲突就先做 C。醒来"收菜"，通过后自动合并。
两个痛点：① 每一步都要老板复制粘贴；② 老板睡觉/走开时流程停住没人知道。
图解：`docs/autopilot-explainer.html`。

## 1. 自动接棒（解决复制）
- 中台（Multica/面板）是唯一派工入口。上一棒写完交付/验收文件并 Stop → 中台用命令行直接启动下一棒（`claude -p` / `codex exec` / DSH 命令行），传入文件路径，不经老板。
- 一件事一条分支一个 git worktree，互不干扰；主线只经合并改动。
- 验收不过自动退回施工，最多 2 轮，再不过 → `needs-owner`。

## 2. 并行与冲突
- 任务书必须写「改动范围」（目录/模块）和「依赖」（issue 号）。施工后用实际 diff 的文件复核，超出范围 → 验收不过。
- 不重叠 → 并行。重叠或依赖未合并的事 → 排队，调度器先挑别的。
- 不叠在未批分支上开工（A 被退回时 B 白做）。
- 数据库结构、权限、部署配置类：独占，一次一件，必须老板看。
- 施工位并发上限 2（按额度调）；「等老板」超过 5 件暂停开新活，防止一夜堆一大摞。

## 3. 合并
- 技术类（无界面变化）验收通过 → 自动对齐主线、重跑测试 → 自动合并。
- 界面/体验类 → 等老板「看效果」通过 → 同样自动对齐+测试+合并。
- 对齐主线失败或测试变红 → 退回施工。
- 上线（公网部署）始终等老板，可攒多件一起发。

## 4. 老板的交互
- 面板「等你」一栏：看效果、做不做、权限请求、上线，点通过/退回/允许即可，结果写回 issue 标签。
- 权限请求：PreToolUse hook 把请求写进面板并等待老板决定（超时则拒绝并通知），而不是在终端里弹窗干等。这是老板亲自点，不是自动放行；白名单内命令不再询问。
- 手机通知通道：Telegram 或 Muse（Muse 已登录在 Mac mini、额度充足），到时再定；在电脑前只在面板提醒。
- 每天早上一条早报：昨夜合并几件、等你几件、卡住几次。
