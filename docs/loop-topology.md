## A 一句话
```callout ok 你只管方向和效果，其余自己转
evo 是通用循环平台，土布（TB）是第一个住进来的项目，股票（ST）等可以随时 new / import 进来。所有问题进各项目的 GitHub issue 队列，接棒器按任务书自动派工、并行推进不冲突的活、合并并推送到 GitHub。你只在三处点头：做不做、看效果、上线。岗位是位子，坐谁随时换。
```

## B 整体拓扑：谁连着谁
```flow LR
[Agent 读仓库发现] -> *GitHub issue 队列
[网页用户反馈] -> GitHub issue 队列
[你的随口意见 evo feedback] -> GitHub issue 队列
[CI 与线上报警] -> GitHub issue 队列
[夜审错题本 23:30] -> GitHub issue 队列
[外部 Agent：Muse / Grok / DSH Bot] -> GitHub issue 队列: 只能开 issue，默认不可信
GitHub issue 队列 -> *evo 接棒器
evo 接棒器 -> Orca 编排
Orca 编排 -> 决策岗
Orca 编排 -> 施工岗 -> 验收岗
验收岗 --> 施工岗: 不过退回
验收岗 -> 合并
合并 -> [推送 GitHub]
evo 接棒器 -> *面板
evo 接棒器 -> 通知
通知 --> [Telegram 按钮]
通知 --> [邮件 / 晨报]
通知 --> [签名 webhook]
面板 -> (你)
Telegram 按钮 --> 你
evo 接棒器 -> [(outbox 事件流)]
outbox 事件流 --> 外部 Agent：Muse / Grok / DSH Bot: 只读
group Mac mini: evo 接棒器, Orca 编排, 决策岗, 施工岗, 验收岗, 合并, 面板, 通知, outbox 事件流
group 来源: Agent 读仓库发现, 网页用户反馈, 你的随口意见 evo feedback, CI 与线上报警, 夜审错题本 23:30
```

## C 多项目怎么摆
```flow LR
(evo 接棒器) -> TB 土布
evo 接棒器 -> ST 股票
evo 接棒器 -> 下一个项目
TB 土布 -> [(~/.evoloop/projects/TB)]
ST 股票 -> [(~/.evoloop/projects/ST)]
下一个项目 -> [(~/.evoloop/projects/XX)]
```

| 东西 | 全局共用 | 每个项目各一份 |
|---|---|---|
| 配置 | 模型与岗位、通知、夜审时间、整机施工上限 | 仓库、测试命令、推送命令、可信作者、时间窗口 |
| 限流 | 施工并行上限、等你超过 5 件暂停 | 本项目施工上限 |
| 面板 | 左上角切换项目，「全部待办」汇总 | 一个项目一页 |
| 件号 | 统一规则 `<代号>-<类别>-<三位序号>` | 例：TB-FIX-012、ST-FEAT-001 |

## D 一件事的状态机
```flow TB
(新 issue) -> 待分诊
待分诊 -> {产品或体验类?}
{产品或体验类?} -> *等你：做不做: 是
{产品或体验类?} -> 可派工: 纯技术
*等你：做不做 -> 可派工: 做
*等你：做不做 --> [不做，回复原因]: 不做
可派工 -> {在时间窗口内? 有冲突? 岗位限额?}
{在时间窗口内? 有冲突? 岗位限额?} --> 排队 / 等窗口: 否
排队 / 等窗口 --> 可派工: 条件满足
{在时间窗口内? 有冲突? 岗位限额?} -> 施工中: 可以开工
施工中 -> {工作区干净?}
{工作区干净?} --> 施工中: 不干净，返工
{工作区干净?} -> 验收中: 干净
验收中 --> 施工中: 不过，最多 2 轮
验收中 --> *卡住，交决策岗: 超过 2 轮
验收中 -> {用户能感知到?}
{用户能感知到?} -> *等你：看效果: 是
{用户能感知到?} -> 合并: 否
*等你：看效果 -> 合并: 通过
*等你：看效果 --> 施工中: 打回，原话带进返工
合并 -> {代码与验收时一致? 主线测试绿?}
{代码与验收时一致? 主线测试绿?} --> 施工中: 不一致或红
{代码与验收时一致? 主线测试绿?} -> 已合并·等推送: 是
已合并·等推送 -> {远端领先?}
{远端领先?} -> 普通合并远端并重跑测试: 是
普通合并远端并重跑测试 -> 推送
{远端领先?} -> 推送: 否
推送 --> 已合并·等推送: 失败自动重试，3 次通知你
推送 -> 已合并·可收菜: 成功
已合并·可收菜 -> *等你：上线 -> (关闭)
```

## E 你睡一晚，它怎么推进
```sequence

evo -> 你: 进「等你看效果」，0 点到 8 点不推送
note evo: Codex 撞到限额，决策岗暂停到额度恢复，不算失败
evo -> evo: 23:30 夜审：今天的返工和打回写进错题本，走完验收、合并、推送

你 -> evo: 在 Telegram 点「通过」
evo -> evo: 合并、推送 GitHub，09:30 ST-FIX-001 自动开工
```

## F 岗位与担任者（随时可换）
| 岗位 | 干什么 | 现在 | 候选 | 在哪跑 |
|---|---|---|---|---|
| 决策岗 | 任务书、技术栈、权限请求；有待决的件时每 30 分钟批量叫醒 | Codex | Claude Pro | Mac mini |
| 施工岗 | 按任务书改代码，先写会红的测试 | DSH：GLM-5.3 Flash / DeepSeek V4.1（经 magpie） | 其他便宜模型 | Mac mini |
| 验收岗 | 测试、验收、退回，和施工用不同模型 | 与施工反过来 | cc | Mac mini |
| 夜审 | 每晚 23:30 写错题本，同一教训出现 3 天升级到代码规范 | evo retro | — | Mac mini |
| 审查岗 | 定期全仓审查，只建 issue | Hark 每日 10:00（跑顺一周后再定） | Grok、Codex 云端等 | 云端，只读 GitHub |
| 编排 | 派工、依赖、并行 | Orca | Multica | Mac mini |
| 接棒器 / 面板 | 派工、状态、审批台、通知 | evo | — | Mac mini |

## G 外部 Agent 怎么接
```callout info 读可以随便读，写只能开 issue，审批只有你
Muse、Grok Bot、本地 DSH、别人写的插件式 Bot，让它先读项目仓库里的 AGENT_INTERFACE.md 就能接入。读：evo status --json（带 schema_version）、outbox 事件流、GitHub issue。写：只能开 issue，默认当不可信输入，除非作者在可信名单里。删数据、改线上、花钱、对外发布这类要求一律转给你。审批和上线外部 Agent 碰不到。

想让它收到推送，就在通知里加一条带签名的 webhook。仓库是私有的，要先给它读权限。
```

## H 安全红线（机器自己守）
| 情况 | evo 怎么做 |
|---|---|
| 状态文件损坏 | 备份成 .bad-*，整个项目暂停，等 evo resume |
| 验收后偷偷改代码 | patch-id 对不上，拦下返工 |
| 推送 | 永不 force push；远端领先先普通合并再重跑测试 |
| 模型订阅撞限额 | 该岗位暂停到恢复时间，同账号的岗位一起停，不算失败 |
| 某件反复空转、用量异常 | 通知你 |
| 外部 issue 里夹带指令 | 正文当不可信输入；不可信作者自己贴的 autopilot:ready 不算数 |
| 协作契约 | 夜审不会自动改，只向你提议 |
